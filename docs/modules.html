🧠 Where Is the Decision Engine?

The AutonomyController (part of the Pi-side integration layer) is the robot's central decision engine. It sits between MOD-02 (Vision) and MOD-01 (Embedded Hardware), consuming sensor telemetry and vision targets to produce motor commands. It implements a strict priority cascade: Obstacle Avoidance → Victim Approach → Autonomous Patrol. The FSM state transitions in MOD-03 complement this by handling acoustic-triggered interrupts.

MOD-01 Embedded & Hardware — Arduino Mega 2560
▾

The "reflexive core" of the robot. Originally built on STM32F103C6 (Blue Pill), migrated to Arduino Mega 2560 after ST-Link SWD pin damage. Handles all real-time hardware control.

Key Responsibilities

  • 4WD motor control via L298N H-Bridge (PWM speed + GPIO direction)
  • HC-SR04 ultrasonic distance sensing (front + back)
  • MPU6050 IMU for yaw/pitch/roll orientation tracking
  • DHT11 temperature/humidity and MQ-2 smoke/gas sensing
  • MAX4466 microphone array analog sampling
  • JSON telemetry streaming at 300ms intervals over USB Serial
  • Command reception and timed execution (2-second auto-stop)

Key API (Arduino Firmware)

  • sendSensorData() — Aggregates all sensor readings into JSON and transmits to Pi
  • komutuUygula(cmd) — Parses FORWARD/BACKWARD/LEFT/RIGHT/STOP commands
  • setMotors(leftDir, rightDir) — Low-level L298N control with PWM speed=200
  • readDistance(trig, echo) — HC-SR04 pulse timing with 30ms timeout

Important Notes

  • MPU6050 must be on 3.3V (not 5V tolerant)
  • Arduino AVR doesn't support snprintf %f — floats use Serial.print(val, 1)
  • MPU6050 I2C read must complete before ultrasonic pulseIn to avoid timing conflicts
MOD-02 AI & Vision Pipeline
▾

Visual perception and victim classification layer running on Raspberry Pi 5. Implements a two-stage edge AI pipeline.

Two-Stage Detection Pipeline

  • Stage 1 — YOLOv8n: Real-time human detection on Pi Camera V3 frames (640×480). Selects the best person candidate by confidence × bounding box area.
  • Stage 2 — Custom CNN (ONNX): Crops the detected person, resizes to 160×160, and classifies severity: TRAPPED, LYING, or STANDING. Uses a 2-second sliding window for stable predictions.

Decision Support Features

  • Bbox Posture Correction: Width/height ratio overrides CNN when bbox shape strongly suggests standing (ratio < 0.85) or lying (ratio > 1.15)
  • Trapped Protection: TRAPPED predictions are protected from being easily overridden — requires strong counter-evidence
  • Dynamic FPS: Exploration mode at 5 FPS, boosted during assessment
  • Pause/Resume: Vision pauses during STT processing to prevent OOM on Pi 5

Public Interface

  • initialize_camera() — Loads YOLO + ONNX models, starts PiCamera2
  • get_latest_target() → TargetData(pos_x, pos_y, distance_cm, severity, confidence)
  • pause_vision_pipeline() / resume_vision_pipeline()
  • build_augmented_status_report(...) — Merges vision output with sensor data
MOD-03 Acoustics & Navigation
▾

Acoustic sensing and autonomous navigation layer. Provides directional hearing capability that complements vision in smoke-filled environments.

Signal Processing Pipeline

  • Dual MAX4466 microphones sampled via Arduino Mega ADC (A0, A1)
  • Software-based Digital IIR Filter attenuates motor/gearbox noise
  • Bearing computation via phase difference between microphone signals
  • Minimum 3 consecutive confirmations required to trigger acoustic homing

FSM Acoustic States

  • 11 FSM states shared across the project (IDLE, EXPLORE, SPIN_MAP, ACOUSTIC_HOMING, etc.)
  • 3-second cooldown between homing transitions to prevent rapid re-triggering
  • 30-second homing timeout — falls back to EXPLORE if source not found
  • ±10° dead zone — bearings within ±10° drive the robot straight forward

Cross-Platform Implementation

  • C (Arduino): acoustics_iir.h — IIR filter + bearing computation
  • Python (Pi 5): acoustic_homing.py — Navigation bridge + streak tracking
  • C# (Unity): MapManager_AcousticBeam.cs — Bearing visualization
MOD-04 Web Dashboard & Speech-to-Text
▾

Communication bridge and operator-interaction layer. Connects the robot's internal stack with external operator interfaces.

Web Dashboard (Flask + Socket.IO)

  • start_server(port=5001) — Launches Flask/SocketIO server on the Pi 5
  • broadcast_telemetry(report) — Sends AugmentedStatusReport to all connected clients
  • stream_video_frame(jpeg_bytes) — Base64 JPEG streaming over WebSocket
  • on_operator_command_received(payload) — Routes manual override commands

Speech-to-Text (Offline)

  • Vosk offline recognition model loaded on Pi 5
  • PTT audio blobs received from Unity → Base64 decoded → WAV processed
  • Vision pipeline is paused during STT to prevent RAM exhaustion
  • Recognized intent mapped to robot commands (FORWARD, STOP, RETURN_HOME)

WebSocket Events

  • telemetry_update — Periodic robot state broadcast
  • video_frame — JPEG frame stream
  • uart_debug — Raw Arduino sensor data
  • operator_command — Manual control from Unity
  • speech_command_parsed — STT result notification
MOD-05 Unity Digital Twin
▾

Primary operator interface built in Unity Engine. Provides a real-time "Digital Twin" visualization with 2D/3D hybrid dashboard.

Core Scripts

  • RobotManager.cs: Centralized coordinator — distributes data to UI, Map, and Acoustic managers
  • WebSocketClient.cs: Socket.IO client using ClientWebSocket with thread marshaling
  • MapManager.cs: GridToWorldPosition mapping, dictionary-based cell keys for victim pins
  • UIManager.cs: HUD with telemetry gauges, victim status, environmental alerts
  • AudioManager.cs: Manual WAV encoding (EncodeToWav) for 16-bit PCM Push-to-Talk

Features

  • Color-coded victim pins: 🔴 TRAPPED, 🟡 LYING, 🟢 STANDING
  • Acoustic beam visualization showing distress call bearing direction
  • Push-to-Talk (PTT) audio capture → WAV → Base64 → WebSocket → STT
  • Demo/Presentation mode with mock telemetry JSON playback

Data Contract (TelemetryData)

  • posX / posY (float) — 2D grid coordinates
  • temperature (float) — Environmental sensor
  • smokeDetected (bool) — Fire safety indicator
  • victimStatus (enum) — Standing / Lying / Trapped
  • acousticAngle (float) — Distress call direction
