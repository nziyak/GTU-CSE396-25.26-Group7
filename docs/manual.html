USER MANUAL

Installation & Setup Guide

⚠️ SAFETY WARNING: This robot operates with 12V motor power and high-current actuators. Always disconnect the motor battery before modifying wiring. Ensure all common grounds are connected before powering the system. Never power the MPU6050 from 5V — it is NOT 5V tolerant.

1. Arduino Mega Firmware Upload

  1. Install Arduino IDE 2.x (or later) from arduino.cc
  2. Install required libraries via Sketch → Include Library → Manage Libraries:
    MPU6050_light by rfetick, DHT sensor library by Adafruit, Adafruit Unified Sensor
  3. Connect Arduino Mega 2560 to your computer via USB
  4. Select: Tools → Board → Arduino AVR Boards → Arduino Mega or Mega 2560
    Tools → Processor → ATmega2560 (Mega 2560)
    Tools → Port → (select the correct COM port)
  5. Open or paste the firmware code, click Upload ⬆️
  6. After upload completes, disconnect Mega from PC and connect to Raspberry Pi's USB port

2. Raspberry Pi 5 Environment

# Update system sudo apt update && sudo apt upgrade -y # Install Python dependencies pip install flask flask-socketio pyserial ultralytics opencv-python-headless pip install onnxruntime picamera2 # Install Vosk (offline STT) pip install vosk # Download vosk-model-small-en-us-0.15 and place in vosk-model/ # Clone the project repository git clone <repo-url> && cd robot_project1

3. Hardware Wiring Checklist

  1. Connect L298N motor driver: ENA→Pin5, IN1→22, IN2→23, IN3→24, IN4→25, ENB→Pin6
  2. Connect HC-SR04 front: TRIG→9, ECHO→10 (VCC→5V). Back: TRIG→7, ECHO→8
  3. Connect MAX4466 mics to A0 and A1 (VCC→3.3V)
  4. Connect MQ-2 smoke sensor to A2 (VCC→5V, allow 20s warm-up)
  5. Connect DHT11 to Pin 4 (VCC→5V)
  6. Connect MPU6050: SDA→20, SCL→21 (VCC→3.3V only!)
  7. Connect motor battery (12V recommended) to L298N VS terminal
  8. Critical: Tie L298N GND + Mega GND + Battery GND together (common ground)
OPERATION

System Startup Procedure

Pre-Flight Checklist

  1. Verify motor battery voltage is 9-12V (12V recommended — 9V may be insufficient)
  2. Confirm all ground connections are tied (common GND topology)
  3. Ensure the Arduino Mega USB cable is connected to Pi 5
  4. Verify Pi Camera V3 ribbon cable is seated properly in CSI port
  5. Confirm YOLOv8 model (yolov8n.pt) and ONNX model (severity_model.onnx) exist in the project directory

Starting the System

# Step 1: SSH into the Pi 5 or open terminal ssh pi@firebot.local # Step 2: Navigate to project directory cd robot_project1 # Step 3: Start the integrated system python3 pi_main.py # Expected output: # [INFO] pi_main: Vision init successful # [WebDashboard] Starting server on 0.0.0.0:5001 ... # [INFO] pi_main: STM front=45 back=80 mic1=340 ...

Connecting Unity Digital Twin

  1. Open the Unity project and enter Play mode
  2. Set the WebSocket URL to ws://<Pi-IP>:5001
  3. The HUD should start showing live telemetry data within 2 seconds
  4. Use the operator controls to send manual commands (FORWARD, LEFT, etc.)
  5. For demo mode: Use FileNetworkClient with mock JSON data

TROUBLESHOOTING

Common Issues & Solutions

🔴 Motors don't move / run at very low power

✅ Remedy: Check battery voltage — 9V may be insufficient for L298N. Use 12V. Verify ENA/ENB jumpers are removed and PWM pins (5, 6) are connected. Check common ground between battery, L298N, and Mega.

🔴 "Serial port not found" on Pi

✅ Remedy: Run ls /dev/ttyUSB* or ls /dev/ttyACM*. Update the port in pi_main.py. Add user to dialout group: sudo usermod -aG dialout $USER

🔴 MPU6050 readings are all zeros

✅ Remedy: Verify SDA→20 and SCL→21 are not swapped (this happened during our development). Ensure VCC is connected to 3.3V, NOT 5V. Run an I2C scan: address should be 0x68.

🔴 Vision pipeline crashes with OOM

✅ Remedy: The Pi 5 has limited RAM. STT processing and vision should not run simultaneously — the system automatically pauses vision during audio processing. Reduce exploration_fps from 5 to 3 if needed.

🔴 DHT11 returns NaN values

✅ Remedy: DHT11 requires 1-2 seconds between reads. The firmware handles this in the 300ms telemetry cycle. Check the data pin (4) connection. Note: we confirmed the sensor is DHT11 (not DHT22) — the code uses DHT11 type constant.

🔴 "Bad UART JSON" warnings flooding the log

✅ Remedy: This occurs when the Mega's serial output gets corrupted (often during motor startup noise). The system automatically retries. Ensure grounds are properly connected to minimize electrical noise. Float formatting uses Serial.print(val, 1) because AVR doesn't support snprintf %f.

🔴 Ultrasonic readings are unreliable when MPU is active

✅ Remedy: The MPU6050 I2C communication interferes with pulseIn() timing. The firmware reads MPU first, then performs ultrasonic measurements. A 10ms delay between front/back readings also helps.

EDGE CASES

Design Notes & Known Constraints

STM32 → Arduino Mega Migration: The original hardware design used an STM32F103C6 (Blue Pill). The ST-Link SWD pins were electrically damaged, making the MCU unprogrammable. The system was migrated to Arduino Mega 2560 before the demo. All firmware logic was ported from STM32 HAL/LL to Arduino Wiring framework. The sensor and motor connections remain identical.
2-Second Timed Commands: Each motor command executes for exactly 2 seconds then auto-stops. This is a safety feature — if communication is lost, the robot will stop automatically rather than continuing to move. The AutonomyController re-issues commands at 250ms intervals to maintain continuous motion.
Thermal Management: The Pi 5 Active Cooler is essential. YOLOv8 + ONNX inference generates significant heat. Without active cooling, the Pi 5 will thermal-throttle and vision FPS will drop below 2 FPS, making victim detection unreliable.
